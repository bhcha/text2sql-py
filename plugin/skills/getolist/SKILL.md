# getolist — 스터디 Olist 자료 받기

사용자는 인자 없이 /getolist만 부른다. 아래 명령 하나만 실행하고 그 요약을 전달한다.

준비: 이 스킬은 엔진 스킬의 실행 스크립트로만 일한다. 이 SKILL.md가 있는 폴더의 옆 폴더 `p3-engine`의 `scripts/p3`를 `sh`로 부른다(`sh <이 SKILL.md가 있는 폴더>/../p3-engine/scripts/p3 <명령>`, 아래에서 `p3 <명령>`이라고 줄여 쓴다). 사용자가 지금 일하는 폴더(작업 폴더 `.text2sql/`가 있는 폴더)에서 부르고, 명령 인자의 상대 경로는 그 폴더 기준이다. 명령 출력에 `t2s <명령>`이라고 나오면 `p3 <명령>`으로 읽는다. 작업 폴더(`.text2sql/`)가 없다고 나오면 `p3 init`을 돌릴지 한 줄로 묻는다. `p3`가 `no_uv`(uv 없음)나 `setup_failed`(처음 환경 만들기 실패)를 돌려주면 그 메시지를 그대로 안내하고 멈춘다. 스킬 이름은 `/이름`으로 적었다. Codex에서는 `$이름`, 플러그인으로 깔았으면 `/text2sql:이름`으로 부른다.

## 절차

1. 실행한다:

   p3 fetch olist

   명령은 인자를 받지 않는다. 받는 곳과 해시는 엔진에 고정돼 있다. 명령이 "작업 폴더가 없습니다. 먼저 init"으로 끝나면 `p3 init`을 돌릴지 한 줄로 묻고, 좋다고 하면 `p3 init` 뒤 다시 실행한다. 이미 있고 해시가 맞는 파일은 건너뛰므로 여러 번 불러도 된다. 받은 뒤 정답 설정 `.text2sql/gold/olist/gold.toml`(정답 파일 이름, 채점기 이름, 정답 파일 sha256)을 만들고, 이미 있으면 대조한다. 끝까지 가면 10줄 이내 요약과 라이선스 표기를 출력한다.

2. 종료 코드 0이면 출력된 요약을 그대로 사용자에게 보여 준다. 줄여 쓰거나 해석을 덧붙이지 않는다.

3. 종료 코드가 0이 아니면 `중단 N단계:` 줄과 그 아래 조치 줄을 그대로 보여 주고 멈춘다.
   - gh 로그인이 안 됐거나 저장소 접근 권한이 없으면 사용자에게 `! gh auth login`을 안내하고 멈춘다. 로그인을 대신하지 않는다.
   - 받기 실패(`gh N`)면 한 번만 다시 /getolist를 부른다. 두 번째도 실패하면 더 시도하지 말고 사용자에게 보고한다.
   - 해시 불일치면 다시 부르지 않는다. 원격 자료가 바뀌었거나 손상된 것이며, 어떤 파일이 다른지와 다음 할 일을 사용자가 정한다.

## 받은 뒤

- 평가셋 49문항을 돌리고 채점하려면 /connect olist로 바꾼 뒤 /runset을 부른다(/runset이 모델 입력 파일을 붙이고, 끝나면 스터디 채점 규칙으로 채점한다).
- evidence used로 돌릴 때는 모델 입력 파일의 문항 조건을 쓴다. 새로 받을 파일은 없다.
- 이 스킬은 DB 등록·준비(값 색인·열 프로파일)를 하지 않는다. 쓰려면 사용자가 /connect에 `.text2sql/data/olist/olist.db`를 주면, /connect가 밖으로 나가는 것을 알리고 승인을 받은 뒤 등록한다.
- `.text2sql/data/olist/schema.snapshot.json`의 `notes`·`logical_relations`는 사람이 쓴 설명이라 퓨어 조건(문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는 조건)에서는 모델에 주지 않는다.

## 지킬 것

- `.text2sql/gold/` 아래 파일, 받은 zip(`.text2sql/data/*/download/`), 공개 evidence 파일(`.text2sql/data/bird-minidev/hints.public.json`)을 열거나 내용을 출력하지 않는다.
- 사용자에게 명령 인자를 치라고 하지 않는다.
- 기본은 evidence not_used(퓨어 조건: 문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는다)다. 사용자가 evidence(문항 조건)를 주라고 말했을 때만 used로 돈다.
- 새 DB는 밖으로 나가는 것을 알리고 승인을 받은 뒤에만 등록한다. 민감한 DB에 쓰지 않는다.
- DB 파일을 직접 열거나 DB 클라이언트·다른 도구로 스키마를 읽지 않는다.
- 세션 모델이 SQL을 직접 쓰지 않는다. SQL은 `p3 ask`·`p3 run`이 만든다.
- 점수 라벨을 줄이지 않는다. 백엔드·evidence 방식·경로가 다른 점수끼리 우열을 말하지 않고, 원 논문·리더보드·스터디 E0 점수를 덧붙이지 않는다.
- 모델을 알 수 없으면 돌리지 않고 묻는다.
- 채점한 run은 이어 돌릴 수 없다. 같은 run을 두 번 시작하지 않는다.
- 커밋과 푸시는 사용자가 말할 때만 한다.
- 플러그인 폴더와 엔진 스킬 폴더에는 아무것도 쓰지 않고, 엔진 소스를 읽지 않는다. 자료와 기록은 `.text2sql/`에만 생긴다.
- run 폴더의 `records.jsonl`·`items/` 같은 큰 파일을 통째로 읽지 않는다.

## 하지 말 것

- `.text2sql/gold/` 아래 파일과 `.part`·`.rejected-*` 파일을 열어 보거나 내용을 터미널에 출력하지 않는다(정답 SQL·기대 결과가 들어 있다).
- 엔진 스킬 폴더의 파일(받는 곳의 커밋과 해시를 고정한 설정)을 고치지 않는다. 해시를 건너뛰는 옵션·환경변수를 더하지 않는다. 해시가 다르면 멈추는 것이 맞는 동작이다.
- 다른 사본(TS 하네스 등)에서 파일을 복사해 오지 않는다. 이 스킬은 원격에서만 받는다.
- 스터디 저장소에 쓰지 않는다(이슈·PR·커밋 금지). 읽기만 한다.
