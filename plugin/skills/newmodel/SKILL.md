# newmodel — 새 모델의 하네스 경로 정하기

사용자는 /newmodel만 부른다. 이 스킬은 `p3 route-start` → `p3 route-status` → `p3 route-judge` → (기록할 수 있는 판정이면 바로) `p3 route-apply`만 부르며 run 폴더의 파일을 열지 않는다.

준비: 이 스킬은 엔진 스킬의 실행 스크립트로만 일한다. 이 SKILL.md가 있는 폴더의 옆 폴더 `p3-engine`의 `scripts/p3`를 `sh`로 부른다(`sh <이 SKILL.md가 있는 폴더>/../p3-engine/scripts/p3 <명령>`, 아래에서 `p3 <명령>`이라고 줄여 쓴다). 사용자가 지금 일하는 폴더(작업 폴더 `.text2sql/`가 있는 폴더)에서 부르고, 명령 인자의 상대 경로는 그 폴더 기준이다. 명령 출력에 `t2s <명령>`이라고 나오면 `p3 <명령>`으로 읽는다. 작업 폴더(`.text2sql/`)가 없다고 나오면 `p3 init`을 돌릴지 한 줄로 묻는다. `p3`가 `no_uv`(uv 없음)나 `setup_failed`(처음 환경 만들기 실패)를 돌려주면 그 메시지를 그대로 안내하고 멈춘다. 스킬 이름은 `/이름`으로 적었다. Codex에서는 `$이름`, 플러그인으로 깔았으면 `/text2sql:이름`으로 부른다.

말 정리: 여기서 "단일 호출"은 하네스 없이 질문과 CREATE 원문만 주는 호출 하나다. "퓨어 조건"(evidence not_used: 문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는 조건)과 다른 말이다. 두 run 모두 기본은 evidence not_used다.

## 무엇을 할지 고르기

- 시작 요청("재줘", "돌려줘", "새 모델", "앞 N문항만") → "시작".
- 진행 질문("어디까지", "진행") → "진행".
- 결과·판정 요청("판정", "결과", "하네스 쓸지") → "판정".
- 기록 요청("기록해줘", "harness.toml에 써줘") → "판정"(판정 뒤 기록할 수 있으면 "기록"이 이어진다).
- 말이 없으면 먼저 `p3 route-status`를 본다. "시작한 짝(route-start)이 없습니다"면 "시작", 진행 중이면 그 출력을 보여 준다, 마지막 줄이 "두 run 모두 채점 끝"이면 "판정"으로 간다.

## 시작

1. 준비를 확인한다:

   p3 prepare

   "자료 없음"이면 "먼저 /getbird로 BIRD 자료를 받아야 합니다"라고 알리고 멈춘다.
2. 모델을 정한다(아래 "모델 정하기").
3. evidence 방식을 정한다. 기본은 not_used다. 사용자가 이번 대화에서 evidence(문항 조건)를 주라고 말했을 때만 used로 돌린다(`--evidence used`, 두 run 모두). used 판정은 not_used 판정과 따로 기록되고 서로 견주지 않는다.
4. 규모를 한 줄로 알린다. BIRD 전체면 "BIRD 500문항을 하네스와 단일 호출로 함께 돌립니다. 하네스 약 1,000~1,500회, 단일 호출 500회 호출입니다. 두 run을 함께 돌리므로 사용량 한도에 더 빨리 닿을 수 있습니다." 묻지 않고 바로 시작한다.
5. 시작한다:

   p3 route-start <모델 인자> [--limit N] [--evidence used]

   - "앞 N문항만"이면 `--limit N`(N에는 숫자만 쓴다. 사용자가 쓴 글을 그대로 넣지 않는다). 소표본 판정은 기록할 수 없다(명령이 거절한다).
   - 지금 데이터셋이 `olist`면 늘 `--questions .text2sql/data/olist/model_inputs.v0.3.json`을 붙인다. 파일이 없으면 "먼저 /getolist로 스터디 평가셋을 받아야 합니다"라고 알리고 멈춘다(파일 존재만 보고 열지 않는다).
   - "이미 도는 run이 있습니다"가 나오면 새로 시작하지 않고 그 줄을 보여 준다.
   - "모델 호출 확인 실패"가 나오면 그 줄을 그대로 보여 주고 멈춘다.
6. 출력을 그대로 보여 준다(모델 줄, 두 경로 줄, 밖으로 나가는 것, 시작 줄 둘, 짝 이름 줄). 명령은 분리된 프로세스 둘을 띄우고 바로 돌아온다. 기다리거나 route-status를 되풀이해 부르지 않는다.

## 진행

   p3 route-status

출력을 그대로 보여 준다. 한 run이 "멈춤(사용량 한도)"이면 한도가 풀린 뒤 그 run을 이어 돌릴 수 있다고 알리고, 사용자가 좋다고 하면 그 run 이름으로 `p3 resume --run-id <이름>`을 부른다(이름은 route-status 출력의 run 이름 그대로).

## 판정

   p3 route-judge

출력을 그대로 보여 준다. 두 run의 라벨 전체와 "새로 맞음·새로 틀림" 문장, 비용 줄, 경로 판정 줄을 자르지 않는다.

플러그인 설치본에서 잰 점수는 대표 측정이 아니다. 대표 측정은 text2sql-py 저장소 클론에서 한다.

- "아직 생성 중입니다"가 나오면 route-status 출력을 보여 준다.
- "멈춘 run입니다"가 나오면 채점하지 않고 그 줄을 그대로 보여 준 뒤 "진행" 절의 resume 안내(한도가 풀린 뒤 사용자가 좋다고 하면 `p3 resume --run-id <이름>`)를 따른다.
- "아직 채점 전입니다: t2s score --run <이름>"이 나오면 그 이름으로 `p3 score --run <이름>`을 한 번 돌린 뒤(약 2~3분, 명령 시간 제한을 10분으로 준다) route-judge를 다시 부른다.
- "이 데이터셋은 정답이 없어 경로를 판정할 수 없습니다"가 나오면(종료 코드 4) 채점하지 않고 그 줄을 그대로 보여 준 뒤 멈춘다. 기록하지 않는다.
- "evidence 조건이 달라 견주지 않는다"가 나오면 그대로 보여 주고 멈춘다.
- "기록에 쓸 수 없음: …"이 나오면 그 줄을 그대로 보여 주고 기록하지 않는다(소표본, 가짜 백엔드, 미커밋 코드, 누설, 판정 보류 등).
- route-judge가 0으로 끝나고 출력에 "기록에 쓸 수 없음" 줄이 없으면 묻지 않고 바로 "기록"으로 간다. 0이 아니면(판정 파일이 이미 있고 내용이 다름 등) 기록하지 않는다.
- Olist 판정은 p만 쓰고, p ≥ 0.05면 "판정 보류"다. 보류면 harness.toml에 쓰지 않고 전체 P3를 유지한다고 알린다.
- 판정은 1회 실행 측정으로 정한 설정값이다. "어느 모델이 낫다", 원 논문·리더보드 점수를 덧붙이지 않는다.

## 기록

판정 바로 뒤에 사용자에게 묻지 않고 한 번에 쓴다(사용자 결정: 측정하고 결과를 바로 저장한다).

1. 쓴다:

   p3 route-apply --yes

   방금 판정한 짝(마지막 짝)의 판정 파일을 다시 읽고, 기록할 수 없는 판정(소표본, 가짜 백엔드, 미커밋 코드, 누설, 판정 보류, 멈춘 run 등)이면 명령이 거절하고 쓰지 않는다. 근거는 배열에 더하기만 하고(같은 측정의 근거가 이미 있으면 거절), 참조 프로필 `p3-ref`에는 쓰지 않는다. 사용자가 프로필 이름을 말했으면 `--profile '<이름>'`(작은따옴표 안에 말한 그대로. 이름 속 작은따옴표 `'`는 `'\''`로 바꿔 쓴다)을 붙인다.
2. 출력 전체(프로필 이름, 새 프로필인지, 더한·바꾼 줄 전부, 마지막 줄)를 자르지 않고 그대로 보여 준다. "쓰지 않음: …"이나 "기록에 쓸 수 없는 판정입니다"가 나오면 그 줄을 보여 주고 멈춘다.
3. 쓴 뒤 따로 지어 낸 안내를 덧붙이지 않고, 명령의 마지막 줄(쓴 것과 커밋 안내)을 그대로 보여 준다. 플러그인 설치본에서는 작업 폴더의 `.text2sql/harness.toml`에 쓴다. 커밋하지 않는다.
4. 경로는 그 프로필을 이름으로 골랐을 때(`/runset`·`/text2sql`에서 "<프로필 이름>으로"라고 말할 때), 그리고 모델 이름을 말해(추론 단계를 말하지 않았으면 이 스킬처럼 medium으로 보고) 백엔드·모델·추론 단계가 글자 그대로 같은 프로필의 근거와 맞을 때 따른다. 세션 모델 run은 늘 전체 P3다.

## 모델 정하기 (사용자에게 인자를 묻지 않는다)

1. 사용자가 이번 대화에서 모델을 말했으면 그 모델로 돈다. 말 → 인자:
   - 오푸스, opus → `--backend claude-code --model claude-opus-5-5`
   - 테라, terra → `--backend codex-cli --model gpt-5.6-terra`
   - 솔, sol → `--backend codex-cli --model gpt-5.6-sol`
   - 루나, luna → `--backend codex-cli --model gpt-5.6-luna`
   - 아스트라, astra → `--backend codex-cli --model gpt-6-astra`
   - 그 밖의 전체 모델 이름은 그대로 작은따옴표 안에 넣어 `--model '<이름>'`으로 쓴다. 이름 속 작은따옴표 `'`는 `'\''`로 바꿔 쓴다. `claude-`로 시작하면 `--backend claude-code`, `gpt-`로 시작하면 `--backend codex-cli`.

   추론 단계를 말했으면(low·medium·high·xhigh·max) `--effort` 그 값, 말하지 않았으면 `--effort medium`. 이 경우들에 `--model-source conversation`을 붙인다. 판정과 기록은 백엔드·모델·추론 단계를 글자 그대로 쓰므로 모델 이름을 줄이거나 바꾸지 않는다.
2. 모델 말이 없으면 지금 네가 돌고 있는 모델을 `--model <전체 이름>`으로 반드시 명시하고 `--model-source session-self`를 붙인다. Claude Code 세션이면 `--backend claude-code`, Codex 세션이면 `--backend codex-cli`(추론 단계를 알면 `--effort`로 적는다).
3. 모델 이름을 알아듣지 못하면 돌리지 않고 한 줄로 되묻는다. 임의로 고르지 않는다.
4. 명령의 첫 줄(모델 · 추론 · 백엔드 · 출처)이 사용자가 말한 모델과 다르면 `p3 stop --run-id <이름>`으로 두 run을 멈추고 알린다.

## 지킬 것

- `.text2sql/gold/` 아래 파일, 받은 zip(`.text2sql/data/*/download/`), 공개 evidence 파일(`.text2sql/data/bird-minidev/hints.public.json`)을 열거나 내용을 출력하지 않는다.
- 사용자에게 명령 인자를 치라고 하지 않는다.
- 기본은 evidence not_used(퓨어 조건: 문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는다)다. 사용자가 evidence(문항 조건)를 주라고 말했을 때만 used로 돈다.
- 새 DB는 밖으로 나가는 것을 알리고 승인을 받은 뒤에만 등록한다. 민감한 DB에 쓰지 않는다.
- DB 파일을 직접 열거나 DB 클라이언트·다른 도구로 스키마를 읽지 않는다.
- 세션 모델이 SQL을 직접 쓰지 않는다. SQL은 `p3 ask`·`p3 run`이 만든다.
- 점수 라벨을 줄이지 않는다. 백엔드·evidence 방식·경로가 다른 점수끼리 우열을 말하지 않고, 원 논문·리더보드·스터디 E0 점수를 덧붙이지 않는다.
- 모델을 알 수 없으면 돌리지 않고 묻는다.
- 채점한 run은 이어 돌릴 수 없다. 같은 run을 두 번 시작하지 않는다.
- 커밋과 푸시는 사용자가 말할 때만 한다.
- 플러그인 폴더와 엔진 스킬 폴더에는 아무것도 쓰지 않고, 엔진 소스를 읽지 않는다. 자료와 기록은 `.text2sql/`에만 생긴다.
- run 폴더의 `records.jsonl`·`items/` 같은 큰 파일을 통째로 읽지 않는다.

## 하지 말 것

- run 폴더의 `records.jsonl`, `report.md`, `report.json`, `ex.jsonl`, 판정 파일, `items/` 아래 파일을 읽지 않는다. 명령 출력만 쓴다.
- `.text2sql/gold/` 아래 파일과 공개 evidence 파일을 열거나 내용을 출력하지 않는다.
- 기록할 수 없는 판정("기록에 쓸 수 없음" 줄이 있거나 route-judge가 0이 아님)에 `route-apply`를 부르지 않는다. harness.toml을 손으로 고치지 않는다.
- 두 run이 도는 동안 플러그인을 업데이트하거나 엔진 스킬 폴더를 건드리지 않는다.
- 참조 프로필 `p3-ref`에는 쓰지 않는다(명령이 거절한다).
- 점수 라벨을 줄여 쓰지 않는다. 원 논문·리더보드 점수, 스터디 E0 점수를 덧붙이지 않는다.
- `--backend`·`--model`·`--effort`·`--model-source`·`--limit`·`--questions`·`--evidence`·`--profile`·`--run-id`·`--yes`는 이 스킬과 명령 사이의 내부 계약이다. 사용자에게 치라고 요구하지 않는다.
