# getmetrics — 승인 지표 정의 받아들이기

사용자는 인자 없이 /getmetrics만 부른다. 지금 바라보는 데이터셋에 맞는 승인 지표 정의를 Graph MCP에서 받아, 검사하고, 승인을 받은 뒤 받아들인다. 지표를 묻는 질문("매출 얼마야", "주문 수 알려줘")은 이 스킬이 아니라 /ask가 한다.

준비: 이 스킬은 엔진 스킬의 실행 스크립트로만 일한다. 이 SKILL.md가 있는 폴더의 옆 폴더 `p3-engine`의 `scripts/p3`를 `sh`로 부른다(`sh <이 SKILL.md가 있는 폴더>/../p3-engine/scripts/p3 <명령>`, 아래에서 `p3 <명령>`이라고 줄여 쓴다). 사용자가 지금 일하는 폴더(작업 폴더 `.text2sql/`가 있는 폴더)에서 부르고, 명령 인자의 상대 경로는 그 폴더 기준이다. 명령 출력에 `t2s <명령>`이라고 나오면 `p3 <명령>`으로 읽는다. 작업 폴더(`.text2sql/`)가 없다고 나오면 `p3 init`을 돌릴지 한 줄로 묻는다. `p3`가 `no_uv`(uv 없음)나 `setup_failed`(처음 환경 만들기 실패)를 돌려주면 그 메시지를 그대로 안내하고 멈춘다. 스킬 이름은 `/이름`으로 적었다. Codex에서는 `$이름`, 플러그인으로 깔았으면 `/text2sql:이름`으로 부른다.

플러그인 폴더의 `scripts/t2s`는 지표 길의 도구다(엔진의 `p3`와 다른 프로그램이다). 여기서는 `export` 하나만 부른다. 명령 출력의 `t2s <명령>`을 `p3 <명령>`으로 읽는 규칙은 엔진 출력에만 해당한다.

## 절차

1. 지금 데이터셋을 본다:

   p3 datasets

   첫 줄이 "지금 바라보는 데이터셋: 없음"이면 "먼저 /connect로 데이터셋을 정해 주세요"라고 알리고 멈춘다. `bird-minidev`면 "BIRD Mini-Dev에는 지표 정의가 없습니다"라고 알리고 멈춘다. 그 밖이면 그 이름을 `<이름>`으로 쓴다.
2. 플러그인 폴더(이 SKILL.md에서 두 단계 위)에 `scripts/t2s`가 있는지 파일 존재만 본다. 없으면 아래 표의 "도구 없음" 줄을 보이고 멈춘다. 있으면 받는다. `DATABASE_URL`은 주지 않는다. 이 호출은 Graph MCP 서버에 토큰과 모델 이름만 보내고 DB의 내용은 보내지 않는다:

   sh <이 SKILL.md가 있는 폴더>/../../scripts/t2s export --out '.text2sql/var/semantic-inbox/<이름>.json'

   출력 JSON(한 줄)은 명령의 표준 출력에서 바로 읽는다. 파일로 옮기지 않고, 꼭 파일이 필요하면 `.text2sql/var/` 아래에만 쓴다. 작업 폴더 밖(`/tmp` 같은 곳)에는 아무것도 쓰지 않는다.
   0이 아니면 출력 JSON의 `error.kind`에 따라 아래 줄을 그대로 보이고 멈춘다. 다시 부르지 않는다. 출력 JSON 전체나 오류 글(`error.message`)은 보이지 않는다. 로컬 정의 파일(`*.ossie.yaml` 같은 것)을 찾거나 대신 쓰지 않는다.

| 경우 | 보일 줄 |
|---|---|
| 토큰이 없거나 연결 실패(`graph_unavailable`) | `Graph MCP에 연결하지 못해 지표 정의를 받아 오지 못했습니다. 받아들인 것은 없습니다.` |
| 활성 모델 없음(`no_active_model`) | `Graph MCP에 활성 지표 모델이 없습니다.` |
| 도구 없음(`scripts/t2s` 없음, `no_uv`, `setup_failed`, 그 밖의 종류) | `지표 길 도구를 쓸 수 없어 지표 정의를 받아 오지 못했습니다. 받아들인 것은 없습니다.` |
| 정의를 SQL로 바꾸지 못함(`bad_definition`) | `활성 지표 모델의 승인 지표 가운데 SQL로 바꿀 수 없는 것이 있어 지표 정의를 받아들이지 않았습니다.` |

3. 받은 정의를 검사하고 고지를 받는다:

   p3 semantic-import '<이름>'

   종료 코드 3이면 고지문 네 줄(받아들일 지표 정의, 밖으로 나가는 것, 말하지 않으면 쓰지 않음, 내보내면 안 되는 정의 금지)을 그대로 보여 주고 "진행할까요?"를 묻는다. 그 아래의 "승인하면 --yes를 붙여 다시 실행" 줄은 사용자에게 칠 명령으로 보이지 않는다(승인을 받으면 이 스킬이 직접 돌린다).
   종료 코드 1이나 2면 마지막 오류 줄(예: "승인 전 항목이 들어 있어 받아들이지 않습니다", "정의의 테이블 … 이 DB에 없어 받아들이지 않습니다", "BIRD Mini-Dev에는 지표 정의가 없습니다")을 그대로 보이고, 받기 자리를 비운 뒤 멈춘다:

   p3 semantic-remove '<이름>' --inbox

4. 사용자가 진행하라고 답한 뒤에만:

   p3 semantic-import '<이름>' --yes

   출력("받아들임: …", 바꾸었으면 "바꿈: 이전 정의 sha256 …")을 그대로 보여 준다. 사용자가 거절하면 `p3 semantic-remove '<이름>' --inbox`를 돌리고 끝낸다.
5. 끝으로 "지표 정의를 넣어 돌리려면 /text2sql이나 /runset에 '지표 정의 넣어서'라고 말하세요. 말하지 않으면 넣지 않습니다."를 알린다.

받아들인 정의를 지우라고 하면 `p3 semantic-remove '<이름>'`을 돌린다.

## 지킬 것

- `.text2sql/gold/` 아래 파일, 받은 zip(`.text2sql/data/*/download/`), 공개 evidence 파일(`.text2sql/data/bird-minidev/hints.public.json`)을 열거나 내용을 출력하지 않는다.
- 사용자에게 명령 인자를 치라고 하지 않는다.
- 기본은 evidence not_used(퓨어 조건: 문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는다)다. 사용자가 evidence(문항 조건)를 주라고 말했을 때만 used로 돈다.
- 기본은 semantic not_used다. 사용자가 지표 정의를 넣으라고 말했을 때만 semantic used로 돈다. evidence와 함께 쓰지 않는다.
- 지표 정의 파일(`.text2sql/data/*/semantic.approved.json`, `.text2sql/var/semantic-inbox/` 아래 파일)을 통째로 읽거나 내용을 출력하지 않는다. 명령이 낸 요약 줄만 보인다.
- 새 DB는 밖으로 나가는 것을 알리고 승인을 받은 뒤에만 등록한다. 민감한 DB에 쓰지 않는다.
- DB 파일을 직접 열거나 DB 클라이언트·다른 도구로 스키마를 읽지 않는다.
- 세션 모델이 SQL을 직접 쓰지 않는다. SQL은 `p3 ask`·`p3 run`이 만든다.
- 점수 라벨을 줄이지 않는다. 백엔드·evidence 방식·경로가 다른 점수끼리 우열을 말하지 않고, 원 논문·리더보드·스터디 E0 점수를 덧붙이지 않는다.
- 모델을 알 수 없으면 돌리지 않고 묻는다.
- 채점한 run은 이어 돌릴 수 없다. 같은 run을 두 번 시작하지 않는다.
- 커밋과 푸시는 사용자가 말할 때만 한다.
- 플러그인 폴더와 엔진 스킬 폴더에는 아무것도 쓰지 않고, 엔진 소스를 읽지 않는다. 자료와 기록은 `.text2sql/`에만 생긴다.
- run 폴더의 `records.jsonl`·`items/` 같은 큰 파일을 통째로 읽지 않는다.

## 하지 말 것

- 사용자 승인 없이 `--yes`를 붙이지 않는다. 고지문 아래의 `--yes` 줄을 사용자에게 치라고 하지 않는다.
- 승인 전 지표를 쓰자고 권하지 않는다. 뺀 수만 고지문대로 알린다.
- Graph MCP 도구를 직접 부르지 않는다. 플러그인 폴더의 `scripts/t2s`는 `export` 하나만 부른다.
- 로컬 정의 파일(`*.ossie.yaml` 같은 것)이나 다른 사본에서 정의를 가져오지 않는다. 정의는 `t2s export`로만 받는다.
- 받기 자리와 받아들인 정의 파일을 열어 내용을 보이거나 손으로 고치지 않는다.
- 이 스킬에서 질문에 답하거나 SQL을 만들지 않는다. 지표 질문은 /ask, 하네스 길의 질문은 /text2sql이 한다.
- 정의를 받았다고 /text2sql이나 /runset을 semantic used로 돌리지 않는다. 사용자가 말할 때만 쓴다.
