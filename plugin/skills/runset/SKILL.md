# runset — 지금 데이터셋 전체 실행

사용자는 /runset만 부른다. 이 스킬은 `p3 run`(start) → `p3 status` → `p3 report`만 부르며 run 폴더의 `records.jsonl`·`report.md`·`items/`를 열지 않는다(문항 수백 개가 세션 맥락을 채운다).

준비: 이 스킬은 엔진 스킬의 실행 스크립트로만 일한다. 이 SKILL.md가 있는 폴더의 옆 폴더 `p3-engine`의 `scripts/p3`를 `sh`로 부른다(`sh <이 SKILL.md가 있는 폴더>/../p3-engine/scripts/p3 <명령>`, 아래에서 `p3 <명령>`이라고 줄여 쓴다). 사용자가 지금 일하는 폴더(작업 폴더 `.text2sql/`가 있는 폴더)에서 부르고, 명령 인자의 상대 경로는 그 폴더 기준이다. 명령 출력에 `t2s <명령>`이라고 나오면 `p3 <명령>`으로 읽는다. 작업 폴더(`.text2sql/`)가 없다고 나오면 `p3 init`을 돌릴지 한 줄로 묻는다. `p3`가 `no_uv`(uv 없음)나 `setup_failed`(처음 환경 만들기 실패)를 돌려주면 그 메시지를 그대로 안내하고 멈춘다. 스킬 이름은 `/이름`으로 적었다. Codex에서는 `$이름`, 플러그인으로 깔았으면 `/text2sql:이름`으로 부른다.

## 무엇을 할지 고르기

- 시작 요청("돌려줘", "전체", "앞 N문항만", "소표본") → "시작".
- 진행 질문("어디까지", "진행", "status") → "진행".
- 결과 요청("보고", "결과", "점수", "report") → "보고".
- 멈춤 요청 → `p3 stop`.
- 이어 돌리기 요청 → `p3 resume`. 거절 까닭이 나오면 그대로 보여 준다.
- 말이 없으면 먼저 `p3 status`를 본다. 첫 줄이 "진행 중"이면 그 출력을 보여 준다. "끝남"이면 "보고"로 간다. "시작한 run이 없습니다"이거나 이미 보고까지 한 run이면 "시작"으로 간다.

## 시작

1. 준비를 확인한다(준비된 것은 건너뛰므로 여러 번 불러도 된다. BIRD 첫 준비는 약 2분):

   p3 prepare

   "자료 없음"으로 멈추면 "먼저 /getbird로 BIRD 자료를 받아야 합니다"라고 알리고 멈춘다. "임베딩 모델이 없다"로 멈추면 "모델 파일 417MB를 받아야 합니다"라고 알리고, 사용자가 좋다고 하면 `p3 fetch model` 뒤 다시 한다.
2. 모델을 정한다(아래 "모델 정하기").
3. evidence 방식을 정한다(아래 "evidence 정하기").
4. 규모를 한 줄로 알린다. BIRD 전체면 "500문항, 약 1,000~1,500회 호출, 30~70분 예상입니다. evidence not_used(또는 used)로 돕니다.", Olist면 "49문항, 약 100~150회 호출입니다. evidence not_used(또는 used)로 돕니다." 묻지 않고 바로 시작한다(/runset을 부른 것이 시작 요청이다).
5. 시작한다:

   p3 run <모델 인자> [--limit N] [--evidence used]

   - "앞 N문항만", "N개만"이면 `--limit N`(N에는 숫자만 쓴다. 사용자가 쓴 글을 그대로 넣지 않는다). "소표본"이면 `--limit 20`. 아니면 `--limit` 없이 지금 데이터셋 전체.
   - evidence used로 정했으면 `--evidence used`를 붙인다. not_used면 붙이지 않는다(기본이 not_used다).
   - 지금 데이터셋이 `olist`면(1단계 `prepare` 출력이나 `p3 datasets`의 "지금 바라보는 데이터셋" 줄) 늘 `--questions .text2sql/data/olist/model_inputs.v0.3.json`을 붙인다. 이 파일로 돌린 run만 스터디 채점기가 채점한다. 파일이 없으면 "먼저 /getolist로 스터디 평가셋을 받아야 합니다"라고 알리고 멈춘다(파일 존재만 보고 열지 않는다). 문항 조건(task_conditions)은 말이 없으면 주지 않는다(evidence not_used). 사용자가 문항 조건을 주라고 말했을 때만 `--evidence used`를 붙인다.
   - "먼저 /getbird(다시 부르면 evidence 파일을 만든다)"가 나오면 그 줄을 보여 주고 멈춘다. 이미 BIRD를 받은 사람도 /getbird를 한 번 더 부르면 공개 evidence 파일이 생긴다.
   - "이 문항에는 evidence가 없습니다"가 나오면(/connect로 붙인 DB, 텍스트 문항) evidence used로 돌 수 없다고 알리고 멈춘다.
   - "이 데이터셋에는 문항 파일이 없습니다"가 나오면(/connect로 붙인 DB) 질문이 한 줄에 하나씩 든 텍스트 파일 경로를 한 줄로 묻고, 받은 경로를 작은따옴표로 감싸 `--questions '<경로>'`로 붙여 다시 한다(큰따옴표 안에서는 셸이 `$`·`` ` ``·`\`·`!`를 바꿔 엔진이 다른 글을 받는다. 경로 속 작은따옴표 `'`는 `'\''`로 바꿔 쓰고, 그 밖에는 사용자가 쓴 그대로 넣는다).
   - "이미 도는 run이 있습니다"가 나오면 새로 시작하지 않고 "진행"으로 간다.
   - "모델 호출 확인 실패"가 나오면 그 줄을 그대로 보여 주고 멈춘다(분리 실행 전의 짧은 확인 호출이 실패한 것이다. 사용량 한도면 풀린 뒤 다시 부른다).
   - 그 아래에 "안내: codex-cli 백엔드는 Codex 샌드박스 안에서 돌지 않습니다" 줄이나 "failed to initialize in-process app-server client" 오류가 나오면 Codex 샌드박스가 파이프라인의 codex 호출을 막은 것이다. 사용자에게 "codex-cli 백엔드는 Codex를 전체 접근으로 열었을 때(또는 샌드박스 없는 터미널에서)만 돕니다"라고 알리고 멈춘다. 다시 돌리지 않는다.
6. 출력을 그대로 보여 준다(첫 줄: 모델·추론·백엔드·출처, 밖으로 나가는 것, 시작 줄). evidence used면 밖으로 나가는 것 줄에 "문항 evidence 글"이 붙고, 시작 줄 끝에 evidence 방식이 붙는다. 명령은 분리된 프로세스를 띄우고 바로 돌아온다. 끝날 때까지 기다리거나 status를 되풀이해 부르지 않는다. 사용자가 물을 때만 status를 부른다.

## 진행

   p3 status

출력을 그대로 보여 준다. 첫 줄이 "끝남"이면 "보고"로 간다. "멈춤(사용량 한도)"이면 한도가 풀린 뒤 이어 돌릴 수 있다고 알린다. "안내: codex-cli 백엔드는 Codex 샌드박스 안에서 돌지 않습니다" 줄이 있으면 시작의 같은 안내를 하고 멈춘다(resume을 부르지 않는다).

## 보고

   p3 report

출력을 그대로 보여 준다. 라벨 전체 문자열과 "새로 맞음·새로 틀림" 문장을 자르지 않는다.

플러그인 설치본에서 잰 점수는 대표 측정이 아니다. 대표 측정은 text2sql-py 저장소 클론에서 한다.

- Olist run이면 셋째 줄이 "정답 대조"(정답 SQL을 같은 규칙으로 돌려 기대 결과와 같은지)다. 비교 대상(기준 run)이 없으면 "비교 대상 없음"이 맞는 출력이다. 스터디 E0 점수와 같은 줄에 두지 않는다.
- evidence used run이면 기본 기준(evidence not_used 기준선)과 견주지 않으므로 "비교 대상 없음(기준은 evidence not_used, 이번은 used라 견주지 않는다)"이 맞는 출력이다. "evidence 조건이 달라 견주지 않는다"가 나오면 그대로 보여 준다. evidence 방식이 다른 run끼리는 우열을 말하지 않는다.

- "아직 생성 중입니다"가 나오면 status 출력을 보여 준다.
- "아직 채점 전입니다"가 나오면 `p3 score`를 한 번 돌린 뒤(약 2~3분, 명령 시간 제한을 10분으로 준다) report를 다시 부른다.
- "정답 없음: 채점 생략"이 나오면 그 아래 실행 요약을 그대로 보여 준다. 채점을 시도하지 않는다.
- 다음을 덧붙이지 않는다: 원 논문·리더보드 점수, 스터디 E0 점수, "TS보다 낫다/못하다", "어느 모델이 낫다".

## evidence 정하기 (사용자에게 인자를 묻지 않는다)

- 기본은 evidence not_used(퓨어 조건)다. BIRD·Olist 둘 다 같다.
- 사용자가 이번 대화에서 "evidence 써서", "evidence 줘서", "조건 줘서", "문항 조건 넣어서", "힌트 줘서", "used로"처럼 evidence(문항 조건)를 주라고 말했을 때만 evidence used로 돈다. 말이 없으면 not_used다.
- "둘 다"라고 하면 어느 것부터 돌릴지 한 줄로 묻는다(한 번에 run 하나만 돈다).
- evidence used run에서는 문항의 evidence 글(BIRD 공식 evidence, Olist 문항 조건)도 모델 제공자 서버로 나간다.
- used 점수는 퓨어 조건 점수라고 부르지 않는다. evidence 방식이 다른 run끼리 우열을 말하지 않는다.

## 모델 정하기 (사용자에게 인자를 묻지 않는다)

1. 사용자가 이번 대화에서 모델을 말했으면 그 모델로 돈다. 말 → 인자:
   - 오푸스, opus → `--backend claude-code --model opus`
   - 테라, terra → `--backend codex-cli --model terra`
   - 솔, sol → `--backend codex-cli --model sol`
   - 루나, luna → `--backend codex-cli --model luna`
   - 아스트라, astra → `--backend codex-cli --model astra`
   - 그 밖의 전체 모델 이름은 그대로 작은따옴표 안에 넣어 `--model '<이름>'`으로 쓴다. 이름 속 작은따옴표 `'`는 `'\''`로 바꿔 쓴다. `claude-`로 시작하면 `--backend claude-code`, `gpt-`로 시작하면 `--backend codex-cli`.

   추론 단계를 말했으면(low·medium·high·xhigh·max) `--effort` 그 값, 말하지 않았으면 `--effort medium --effort-source default-medium`(추론 단계를 말하지 않았다는 표시. 이때는 추론 단계를 기본값 medium으로 보고 아래의 모델 이름 맞추기를 한다. newmodel이 같은 규칙으로 재고 저장한다). 조합이 gpt-5.6-terra·medium·codex-cli면 위 인자 대신 `--profile p3-ref`를 쓴다(원본 재현 조건). 이 경우들에 `--model-source conversation`을 붙인다.

   사용자가 harness.toml의 프로필 이름을 말했으면("p3-claude로", "<이름> 프로필로") 위 인자 대신 `--profile '<이름>'`(작은따옴표 안에 사용자가 말한 그대로. 이름 속 작은따옴표 `'`는 `'\''`로 바꿔 쓴다)과 `--model-source conversation`을 쓴다. 프로필의 경로(single·harness·partial, /newmodel로 정한 것)는 프로필을 이름으로 골랐을 때 따르고, 모델 이름을 말했을 때도(추론 단계를 말하지 않았으면 medium으로 보고) 백엔드·모델·추론 단계가 글자 그대로 같고 근거가 맞는 프로필이 있으면 따른다(명령이 맞춘다. 맞는 프로필 여럿의 경로가 다르면 전체 P3. 추론 단계를 기본값 medium으로 보았으면 "경로 …" 줄 끝에 그렇다고 나온다). 세션 모델이면 전체 P3다. `p3-ref`는 경로를 갖지 않으므로 위의 p3-ref 규칙은 그대로다. 첫 줄 아래에 "경로 …" 줄이 나오면 그대로 보여 준다.
2. 모델 말이 없으면 지금 네가 돌고 있는 모델을 `--model <전체 이름>`으로 반드시 명시하고 `--model-source session-self`를 붙인다.
   Claude Code 세션이면 `--backend claude-code`. 추론 단계는 적지 않는다(명령이 세션 설정에서 읽는다).
   Codex 세션이면 `--backend codex-cli`. 추론 단계를 알면 `--effort`로 적고, 모르면 적지 않는다(명령이 설정 파일 값을 쓴다).
3. 모델 이름을 알아듣지 못하면 돌리지 않고 한 줄로 되묻는다. 임의로 고르지 않는다.
4. 명령의 첫 줄(모델 · 추론 · 백엔드 · 출처)을 그대로 사용자에게 보여 준다. 그 줄이 사용자가 말한 모델과 다르면 `p3 stop`으로 멈추고 알린다.

세션 모델이 gpt-5.6-terra·medium이 아니면 그 run은 TS 원본 재현 비교가 아니다. 검증 측정은 사용자가 "terra medium으로"라고 말할 때만 해당한다.

## 지킬 것

- `.text2sql/gold/` 아래 파일, 받은 zip(`.text2sql/data/*/download/`), 공개 evidence 파일(`.text2sql/data/bird-minidev/hints.public.json`)을 열거나 내용을 출력하지 않는다.
- 사용자에게 명령 인자를 치라고 하지 않는다.
- 기본은 evidence not_used(퓨어 조건: 문항의 evidence와 사람이 쓴 설명을 모델에 주지 않는다)다. 사용자가 evidence(문항 조건)를 주라고 말했을 때만 used로 돈다.
- 새 DB는 밖으로 나가는 것을 알리고 승인을 받은 뒤에만 등록한다. 민감한 DB에 쓰지 않는다.
- DB 파일을 직접 열거나 DB 클라이언트·다른 도구로 스키마를 읽지 않는다.
- 세션 모델이 SQL을 직접 쓰지 않는다. SQL은 `p3 ask`·`p3 run`이 만든다.
- 점수 라벨을 줄이지 않는다. 백엔드·evidence 방식·경로가 다른 점수끼리 우열을 말하지 않고, 원 논문·리더보드·스터디 E0 점수를 덧붙이지 않는다.
- 모델을 알 수 없으면 돌리지 않고 묻는다.
- 채점한 run은 이어 돌릴 수 없다. 같은 run을 두 번 시작하지 않는다.
- 커밋과 푸시는 사용자가 말할 때만 한다.
- 플러그인 폴더와 엔진 스킬 폴더에는 아무것도 쓰지 않고, 엔진 소스를 읽지 않는다. 자료와 기록은 `.text2sql/`에만 생긴다.
- run 폴더의 `records.jsonl`·`items/` 같은 큰 파일을 통째로 읽지 않는다.

## 하지 말 것

- `p3` 명령이 실패했을 때 결과를 다른 방법으로 만들지 않는다. SQL을 직접 쓰지 않고, 자료 폴더나 DB 파일을 직접 읽지 않고, 웹을 검색하지 않는다. 오류를 보여 주고 멈춘다.
- run 폴더의 `records.jsonl`, `report.md`, `report.json`, `ex.jsonl`, `items/` 아래 파일을 읽지 않는다. status·report 출력만 쓴다.
- `.text2sql/gold/` 아래 파일을 열거나 내용을 출력하지 않는다.
